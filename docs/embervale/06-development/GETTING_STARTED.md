# Getting started with GameEngine and Embervale

**Status:** Linux headless and dummy-driver client/test builds have been reproduced. See the [dated verification record](BASELINE_VERIFICATION_2026-11-18.md); Windows and visible playtesting remain unverified.\
**Baseline:** `e9d32932e8f9b27e96283313cca320058792a81f` · **Updated:** 18 November 2026

## 1. Choose what you want to run

| Goal | Configuration | SDL3 required? |
|---|---|---|
| Work on simulation and headless tests | Client OFF, graphics tests OFF | No |
| Play the development game and run all test groups | Client ON, graphics tests ON | Yes |
| Validate a starter snapshot | `EmbervaleWorldValidate`, content tools ON | No in headless configuration |
| Play a selected starter snapshot | Client ON; `GameEngine --world <file>` | Yes |
| Inspect starter prices or replay the equipment route | `EmbervaleEconomyReport`, content tools ON | No in headless configuration |
| Export compiled starter content | `EmbervaleWorldExport`, content tools ON (default) | No in headless configuration |
| Play a normal starting character | `GameEngine --profile fresh` (temporary by default) | Yes |
| Play the River Crossing blockout | `GameEngine --world content/worlds/river-crossing.blockout.json --profile fresh --no-save` | Yes |
| Edit maps in Embervale Studio | Python/Tk shell with `EmbervaleWorldMove`; see the [editor guide](../04-studio/VISUAL_WORLD_EDITOR.md) | SDL3 only for game play |

The project uses C++20 and CMake 3.20 or newer. It defines `GameEngineCore`, an optional `GameEngine` client and tests controlled by `BUILD_TESTING`. `GAMEENGINE_BUILD_CLIENT` defaults ON; the default for graphics tests follows that option. Set both flags explicitly when creating a headless build. [Source: CMakeLists.txt](https://github.com/Adzffs/GameEngine/blob/e9d32932e8f9b27e96283313cca320058792a81f/CMakeLists.txt).

Begin in the repository root, the directory containing `CMakeLists.txt`. Keep build output outside source directories and use a separate build directory for each toolchain/configuration. Do not reuse a CMake cache generated by a different compiler.

## 2. Obtain the source and record your revision

For a new checkout, the repository is:

```bash
git clone https://github.com/Adzffs/GameEngine.git
cd GameEngine
git rev-parse HEAD
git status --short
```

If you already have a checkout, inspect its status before switching branches or updating it. Preserve your work; do not reset a working tree simply to make setup instructions match. Record the commit you actually build, since this document's evidence applies to its pinned baseline.

The [Repository guide](../01-current-state/REPOSITORY_GUIDE.md) explains where the main systems live. The [Master roadmap](../02-roadmap/MASTER_ROADMAP.md) separates current features from planned tools.

## 3. Linux headless development

Use a C++20 compiler, CMake and Ninja. On an Ubuntu-like environment, install `build-essential`, `cmake` and `ninja-build`; install equivalent tools through your environment’s normal package manager.

From the repository root:

```bash
cmake -S . -B build-headless -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug \
  -DBUILD_TESTING=ON \
  -DGAMEENGINE_BUILD_CLIENT=OFF \
  -DGAMEENGINE_BUILD_GRAPHICS_TESTS=OFF
cmake --build build-headless --parallel
ctest --test-dir build-headless --output-on-failure -L headless
```

This configuration intentionally does not produce the SDL game window. To list discovered tests without running them, use `ctest --test-dir build-headless -N`. A successful configure or test listing is not a passing test run.

## 4. Windows client with MSYS2 UCRT64

Use the **UCRT64** MSYS2 environment and its matching compiler, CMake, Ninja and SDL3 packages. Keep this environment consistent rather than mixing tools from unrelated MSYS2 subsystems or an old absolute compiler path. Install the following packages in an MSYS2 UCRT64 shell:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc \
  mingw-w64-ucrt-x86_64-cmake \
  mingw-w64-ucrt-x86_64-ninja \
  mingw-w64-ucrt-x86_64-sdl3
```

Then configure and build from the repository root:

```bash
cmake -S . -B build-client -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug \
  -DBUILD_TESTING=ON \
  -DGAMEENGINE_BUILD_CLIENT=ON \
  -DGAMEENGINE_BUILD_GRAPHICS_TESTS=ON
cmake --build build-client --parallel
ctest --test-dir build-client --output-on-failure -L headless
SDL_VIDEODRIVER=dummy ctest --test-dir build-client --output-on-failure -L client
SDL_VIDEODRIVER=dummy ctest --test-dir build-client --output-on-failure -L graphics
```

These shell examples target MSYS2 Bash. The dummy video environment is for automated tests, not normal play. From the repository root, launch the built Windows game with:

```bash
./build-client/GameEngine.exe
```

If SDL3 cannot be found, verify the selected toolchain and the package installation before adding arbitrary include/library paths. CMake requests SDL3 through its config package. The [verification record](BASELINE_VERIFICATION_2026-11-18.md) supplies a tested Linux dummy-driver client setup using a local SDL prefix. A visible desktop/GPU playtest and macOS onboarding remain separate work.

## 5. Understand saves and development boosts

For River Crossing on Windows, use the repository-root **Play-RiverCrossing.cmd**
launcher. It configures/builds a dedicated `build-river-crossing` directory with
the UCRT64 compiler, supplies the runtime DLL path and opens a temporary fresh
character. It works from another current directory and skips test targets.
An older local checkout or executable will not understand the new `--world` and
`--profile` options until its source is updated and rebuilt. The launcher does
not pull Git changes or modify existing saves. See the [launch diagnosis and
confirmed visible startup](LOCAL_RIVER_LAUNCH_2026-11-19.md).

No-argument startup uses the compiled world and `saves/development-player.save`, relative to the process working directory. `--world <snapshot.json>` explicitly validates and loads a supported starter snapshot and defaults to temporary progress with no player save. Add `--save saves/map-playtest.save` to select an isolated persistent playtest, or use `--no-save` for temporary compiled-world play. `--compiled-world` explicitly selects the original content; `--help` lists current options. See [runtime import and launch examples](../04-studio/STARTER_WORLD_IMPORT.md).

Keep ordinary development saves separate from test fixtures. Before a save-related experiment, preserve a copy and record the launch directory. Do not delete your save as a routine troubleshooting step. Normal controlled shutdown is the documented save boundary; a forced termination is not guaranteed to preserve progress. [Source: DevelopmentPlayerPersistence.md](https://github.com/Adzffs/GameEngine/blob/e9d32932e8f9b27e96283313cca320058792a81f/docs/DevelopmentPlayerPersistence.md).

The current `ENABLE_TEST_PLAYER` setting is true. New development-default players receive boosted Woodcutting, Mining and Smithing XP. A newly created development save is consequently not a genuine unboosted starter account. Use `GameEngine --profile fresh` for level-1/zero-XP skills, bronze gathering tools and no developer godsword. Fresh launches have no implicit save, including compiled-world play. Studio defaults to **Fresh player**, with a temporary **Development** option. An explicitly selected existing save restores its saved progress rather than resetting it. The [fresh-player contract](../05-game/FRESH_PLAYER_PROFILE.md) specifies the full starting state; runtime and visible acceptance remain deferred at the owner's request. [Sources: DevelopmentConfig.h](https://github.com/Adzffs/GameEngine/blob/e9d32932e8f9b27e96283313cca320058792a81f/src/Core/DevelopmentConfig.h), [Player.cpp](https://github.com/Adzffs/GameEngine/blob/e9d32932e8f9b27e96283313cca320058792a81f/src/Player/Player.cpp).

## 6. VS Code and other editors

Use the portable CMake commands above as the source of truth. Configure your editor to use the actual local compiler and chosen build directory. If you create a local debug launch configuration, set its executable to that build's output and choose its working directory deliberately because saves are relative to it.

Machine-specific `.vscode` files containing paths such as `c:/GameEngine` are not portable onboarding. Keep personal settings local. Shared presets or editor configurations can be added later when they use workspace-relative paths, match supported toolchains and have been verified. Do not substitute a new untested configuration for a removed stale one merely to preserve the filename.

## 8. Follow the starter equipment journey

Use the fresh River Crossing launcher, then talk to Mara. The next-step card
shows material progress and a destination from the selected map. Press **H** or
left-click the card for the complete sword/shield material plan and quest choices.
Left-click an axe or pickaxe in your bag to equip the appropriate gathering tool.
The sword needs three Bronze bars and one Wooden plank; keep its plank when
making the optional shield. Accept Gathering Basics / Mining Basics before
gathering their ten normal Logs / five Copper. The two rewards total twenty
coins, enough to buy a shield or keep for supplies if you craft your equipment.

The developer reference replay gathers and trades through production commands
without seeding items, coins or XP. Build `EmbervaleEconomyReport` with content
tools enabled, then run `--replay-starter-upgrade --world content/worlds/river-crossing.blockout.json`.
Its tick report does not measure human reading, discovery, cursor handling or
combat. [Commands, route evidence and remaining acceptance](STARTER_UPGRADE_JOURNEY_2026-11-19.md).
