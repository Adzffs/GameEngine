# Playtest report template

## Session

- Date, tester familiarity and session goal:
- Source commit, region version/hash and content candidate name:
- Hardware/window/UI scale and relevant controls:
- Fresh/development/restored profile and exact starting state:
- Assistance allowed, seed if controlled, and elapsed session time:

## Hypotheses

Write each design claim before the test. Examples: a new player can identify the next useful service without coaching; the first deliberate upgrade fits the chosen target; an optional loop offers a worthwhile detour; required service access does not concentrate every trip on one point.

## Observation log

| Time or step | Task/route | Observation | Assistance | Result |
|---|---|---|---|---|
| Fill during the session | Record the actual path | Separate observation from interpretation | Record hints given | Completed, failed or abandoned |

## Measurements

Record time to first useful interaction, gathering/crafting/travel/banking time, upgrade acquisition, resource waits, deaths/recovery, food/coin changes, quest completion and navigation mistakes. Do not combine boosted and fresh-profile results into one baseline.

## Player feedback

Record what the tester expected, where they felt lost, which activity they chose voluntarily, which return trip felt repetitive and what they wanted to try next. Preserve direct quotes only with permission to record them.

## Findings and changes

Rank findings by effect on the intended loop. Link bugs separately from design preferences. Record the smallest change to test next, the rationale and the comparison session. Keep accepted, rejected and inconclusive hypotheses distinct.
