# Task tracking

Use GitHub Issues for individual work items and a GitHub Project board for status, priority, milestone and dependencies. Keep these as the task-status source of truth so the same task is not updated independently in Markdown, an Excel file and GitHub.

## Suggested board columns

- Backlog
- Ready
- In progress
- Review
- Blocked
- Done

## Issue fields

Each feature issue should include: player outcome, scope/non-goals, dependencies, acceptance criteria, tests/evidence, relevant design docs, branch/PR and milestone. Use the feature brief template for larger work.

## Done rule

Close an issue when acceptance evidence is recorded, relevant tests/builds pass, required independent review is complete, and the implementation is merged. Do not use Done to mean only “code written.”

The Library workbook remains useful as a downloadable dashboard and snapshot, but this GitHub board should be authoritative for changing task status.
